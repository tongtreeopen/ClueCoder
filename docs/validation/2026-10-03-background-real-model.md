使用当前 .env 配置的 deepseek-v4-flash、OpenAI-compatible provider、api.deepseek.com；temperature=0，输出上限 1200 token。凭据仅运行时使用，原始值未写入报告。模型与独立 GoalEvaluator 都使用真实 API；无需 mock。

使用已有固定摘要 Docker 镜像，完整值见 protocol.json（归档材料未收录于此副本）。固定检查 python check.py 内等待 15 秒，后台命令要求 timeout=90；每场景独立临时工作区、会话、容器标签和预算。模型可访问临时项目工具，日志与初始哈希位于工作区外。每次最多 12 次模型调用、48000 外部 token 预算、360 秒外部墙钟上限；内部 Goal 保持默认 30000 token、3 次续跑，未为通过测试提高预算。

成功场景要求检查运行时读取 note.txt，真实成功后登记固定命令证据并达成 Goal。失败场景固定检查故意抛 AssertionError，不允许修复。取消场景只启动一次并立即取消。修改场景把 return x * 2 等价改成 return x + x，必须拒绝首次证据并重新检查。模型预先得到工具使用指引，因此本次属于有指导的功能测试，不能证明自主发现工具的能力。

验收使用真实 Docker 状态、SessionJournal 完成事件、实际 work card/Goal 状态、文件字节哈希及工作区外独立执行的源码 Gate。独立源码 Gate 只验证 double 的语义，不能替代模型固定检查，也不能挽救 Goal limit。严格通过还要求模型最终返回约定的单个 JSON；另外列出取消实际行为，避免把格式问题算成基础机制失败。

调用的是 Agent.chat 和 CLI 同一 _bind_work 接线，不是终端交互层端到端测试；没有测试实际软件问题解题、强杀恢复、跨会话续跑或效率改善。

## 直接观察及原因边界

- 成功两轮都完成了后台启动与运行期读取，但持续 background_status 查询，最后触发内部 Goal token limit；退出清理取消了尚未完成的检查。第一轮额外 cat/sha256sum Bash 还将证据标为受干扰。第二轮没有额外 Bash，也因预算而停止，因此不能把全部失败归因于违反指引。
- 故意失败第一轮提前耗尽预算后被退出清理取消，未覆盖其自然失败终态；第二轮取得真实 failed/exit 1，但又执行前台变体 python check.py; echo exit，随后耗尽预算。两轮均没有被验收成功。
- 取消两轮均按序启动、取消、查询，未重跑、未修改文件；返回内容明确没有成功证据，Goal 为 needs_user。模型返回 Markdown/说明文字或围栏 JSON，未满足单个 JSON 格式。
- 修改第一轮取得两次 completed/exit 0，但模型通过额外 Bash sleep 等待，使第二次检查也被标为干扰；第二轮取得过期首次结果后未完成固定后台重检，转而读取和额外 stress 检查。旧证据拒绝符合设计，新鲜固定证据未建立。

这些轨迹支持“短周期轮询与模型额外命令会阻碍完成”的结论；不能单凭本次记录确定改动哪一处便能普遍解决。下一步优先考虑后台查询的有界等待/轮询节流，并保持新鲜度门，再用完全相同协议复测；本轮仅测试，没有修改产品逻辑。

## 探索记录与测试器问题

正式冻结前有探索尝试，均保留为 invalid-crlf-*、invalid-mixed-*，不计入八次评分。最初测试器先对 LF 字符串做哈希再通过 Windows 文本写文件，CRLF 导致未改动文件也被误判变化；后改成实际文件 read_bytes 哈希。停止探索进程的名称过滤也过窄，导致旧父进程与新尝试混入同一输出目录，最终发生目录冲突。确认无残余测试进程、隔离旧输出并清理各自标签容器后，才开始正式串行运行；正式运行中测试器未再修改。

因此，探索取消场景的文件变化评分不成立，不能归因于模型。45 秒探索检查也观察到默认 token 预算耗尽；正式 15 秒协议是单独测试条件，不把探索数据替换或算成通过。包含已保留探索记录的总调用为 119 次、已报告 token 为 389148，usage_unknown 记录为空；它们不是统一协议评分数据。扫描已保存测试目录，未发现当前凭据原值。
