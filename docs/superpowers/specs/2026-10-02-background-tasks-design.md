# TraceCoder 后台命令设计（已批准）

> 历史记录：本文对应当时的设计或验证源码快照，当前代码位于 cluecoder/；历史 revision、哈希及产物路径保留原始 CoreCoder 身份。当前用法以 README 和 CLI 帮助为准；历史成绩不代表当前版本。

## 目标与范围

让长测试或构建启动后立即返回任务 ID，Agent 可继续读取代码，随后查询状态、读取输出或取消。复用严格 CLI 的 Docker 隔离、工具许可和会话日志；不新增依赖。首版任务只属于当前 CLI 进程，不实现定时调度、常驻 Agent、重启续跑或自动唤醒。

用户已批准本文及对应实施计划，采用当前 Agent 串行实现。

## 现有路径

`cli._cli_context` 注册 `DockerBashTool`；无可用后端时注册 `DisabledBashTool`。`Agent._permit` 在执行前检查 Plan Mode 和权限。`DockerExecutor.run` 创建独立容器、收集输出、控制超时及输出上限，最后验证清理。`WorkStateStore._check_succeeded` 目前只接受匹配 Bash 命令的真实工具结果；`goal_evidence` 在后续文件/Bash 操作后使证据失效。

教学来源为根目录 `s11_background_tasks/code.py`：后台线程执行 Bash，保存结果，下一轮收集通知。TraceCoder 保留立即返回 ID 和结果收集思路，使用 Docker 容器而非宿主 shell；不把后台通知伪装成用户指令。

## 方案选择

1. **推荐：扩展现有 Docker 执行器。** 前后台共用启动参数、输出收集和清理路径；一个会话级管理器维护执行句柄，轮询与取消均访问真实任务。
2. 在线程中直接调用现有 `run`：改动少，但没有可取消句柄，运行中输出不可查，不能满足验收。
3. Docker detached 任务服务：方便跨进程恢复，但需要额外的持久恢复、容器发现和资源回收协议，超出首版。

## 工具和生命周期

- `bash(command, timeout=120, run_in_background=false)`：默认行为保持兼容。后台模式验证参数并通过原有 Bash 许可后启动，返回 ID；启动回执不是命令成功证据。
- `background_status(task_id)`：查询状态和退出码，并提供有界的当前合并输出；只读，重复查询不会消费结果。
- `background_cancel(task_id)`：取消运行任务，验证容器终止和清理；终态重复取消返回已有状态。属于变更操作，沿用权限检查。
- 状态包括 running、completed、failed、cancelled、timed_out、output_limit、cleanup_failed。只有真实零退出码且清理已验证才进入 completed；取消和完成的竞态保留真实终态。
- 默认超时和上限沿用现有 120 秒、最大 300 秒、1 MB 输出及展示截断规则。会话最多同时运行 4 个任务，达到上限明确拒绝，避免无限资源增长。
- 子 Agent 共享会话管理器，ID 全会话唯一；管理器及执行句柄加锁。工作区固定为 CLI 启动目录，不继承线程的宿主 cwd。
- CLI 正常退出、异常退出以及 `/reset` 前取消并清理全部活跃任务。切换 Plan Mode 前先清理活跃任务，清理失败拒绝进入只读模式。Python 直接嵌入方须显式关闭管理器。
- 本轮完成通知在下一次请求前由主线程收集，保存为真实后台事件并作为低信任运行结果提供给模型；后台线程不直接写 SessionJournal，不触发模型调用。
- 重启只可读取历史事件，旧 ID 不可继续操作；进程被强杀的清理不作保证，容器命令仍须有自身最大运行时间保护。若无法实现容器内超时保护，后台启动必须拒绝，而不能只依靠宿主线程计时。

## Goal 与工作卡证据

后台结果采用结构化事件：任务 ID、原始命令、启动工具调用 ID、终态、退出码、清理是否成功和输出。Goal 只接受管理器生成并已落盘的 completed 事件，精确匹配验收命令；状态查询文本、模型声明和启动回执均不能作为成功证据。

存在任一活跃后台任务时，Goal 和工作卡不能验收完成，即使已有用户确认。验收后新启动 Bash/后台任务、写文件、取消操作均使旧证据失效。检查执行期间出现文件修改或其他可能修改工作区的命令时，保守拒绝该检查作为新鲜证据，要求在任务全部结束后重跑。清理失败阻止验收，不能以用户确认覆盖。

普通聊天不新增 Goal 完成门；可以报告任务仍在运行，用户可在后续轮次查询。一次性 `-p` 退出时清理仍在运行的任务，不承诺退出后继续执行。

## 验收与实现边界

1. 真实 Docker 慢命令启动后立即返回；其运行期间另一条工具调用能完成；可查询部分输出，结束后退出码和最终输出正确。
2. 取消包含子进程的命令后，命名容器已消失；重复取消不误伤其他任务。超时、非零退出、输出溢出、启动失败及清理失败各有真实终态。
3. 前台 Bash 原有行为及隔离参数保持兼容；无 Docker 不回退宿主。拒绝许可和 Plan Mode 不启动容器。
4. 活跃任务、伪造/查询结果、失败终态、并发修改和旧验收均无法通过 Goal；真实完成事件在无干扰时可登记并通过确定性证据门。
5. CLI 退出、reset、子 Agent 返回和中断的生命周期有针对性验证；后台工作不伪造用户消息、不破坏工具调用配对。
6. 先跑定向回归，再跑项目现有全量检查。真实 Docker 不可用时明确报告集成验收未完成；不以脚本模型证明真实模型效果。

预计触及 `execution.py`、新建会话级后台管理器及工具、`tools/bash.py`、CLI/Agent 接线、权限和工作卡/Goal 证据读取；补一份集中回归文件，并更新已有机制对照文档。避免顺带重构评测、Memory 或 Task。
