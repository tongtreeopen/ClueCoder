# 后台命令与 Goal 修复测评（2026-10-03）

## 修复依据

此前等待方案严格验收为 1/8，不能归因于单一轮询问题。本轮沿实际请求链定位并修改四处：

1. **工作模型续跑 400。** SDK 探针在无工具时成功，带工具时返回 `reasoning_content ... must be passed back`。`LLMResponse` 和流式读取此前丢弃了该字段，现在保留并随真实 assistant 历史回传，同时把它计入上下文估算。记录 `finish_reason` 供诊断；不向用户流式输出思考内容。原始失败及修复成功见 probes.json（归档材料未收录于此副本）、reasoning-green.json（归档材料未收录于此副本）。
2. **评估器没有可解析正文。** 精确重放两个失败请求，500 个输出 token 全用于思考，`finish_reason=length`、正文为空；仅提高到 2000 仍会发生同类失败。官方 DeepSeek 端点的无工具评估请求现在显式关闭 thinking 并启用原生 JSON object，输出上限 2000。工作模型仍保留原思考模式，其他端点不发送这些专用选项。截断明确拒绝，不补造 JSON。见 exact-evaluator-replay.json（归档材料未收录于此副本）、evaluator-green.json（归档材料未收录于此副本）、evaluator-final-green.json（归档材料未收录于此副本）。协议依据：[DeepSeek thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/)、[Create Chat Completion](https://api-docs.deepseek.com/api/create-chat-completion/)。
3. **辅助要求缺上下文。** 评估器之前只收到 Goal、候选和主检查结果，无法核对运行期间读文件等要求。现在提供最多 24 条近期真实消息及必要时额外保留的当前用户请求，单条截到 2000 字符，排除思考内容；辅助上下文 ID 不能充当成功检查证据。`allowed_evidence_event_ids` 必须与确定性证据门给出的集合完全相同。新增评估响应日志及请求错误日志有界、脱敏，便于下次定位。
4. **当前用户请求被最近窗口丢弃。** 中间测评仍为 3/8，五个失败仅为最后回答不是规定 JSON。回放发现数轮工具之后，`ContextAssembler` 的最近消息窗口丢掉了尚未完成的当前用户请求，固定命令和输出格式约束一并消失。新增四个单/多用户、短/长工具历史测试先全部失败，再修复最近窗口与 snip 的边界，保留真实当前请求及工具调用/结果配对；硬 token 上限继续生效，不伪造新的用户消息。见 active-request-red.txt（归档材料未收录于此副本）。

Goal 反馈明确：禁止修复/重跑的失败或取消检查应记录 blocker 并按用户格式报告未验证；后台检查在全部修改后按原命令和模式重新执行。没有放宽成功、新鲜度、干扰或清理门，也没有增加终稿 JSON 自动修补器。
